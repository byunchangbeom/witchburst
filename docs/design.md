## 생동감·방향 후속 제작 · 현재 Root

추가 사용자 피드백은 「정지 이미지가 경로를 따라 움직이는 느낌」과 「위로 이동·공격해도 정면을 본다」다. 두 반려 모두 OPEN이며 새 기술 PASS로 지우지 않는다. 현재 Root가 Producer/Art/Engineer를 겸해 기존 후보ae8083b에서 `work/living-motion`을 분기했다. 기존 BLOCKED task를 재등록/재진입하지 않았고 Harness 호출은 추가하지 않았다. 이 브랜치의 변경은 미커밋·독립 리뷰/통합 전 로컬 제작이다.

- 기존 마녀·정령·적의 디자인과 배경·UI·ShaderMaterial·입자·규칙·저장을 재사용했다. 실제 imagegen 자세 시트를 호스트가 공급하고 `AnimatedSprite2D`·`SpriteFrames`에 통합했다. 기존 한 장 그림은 표현 좌표의 기준 노드로 남지만 전투에서 숨기며, 실제 그림은 새 자세 actor다. 검사도 실제 actor의 AtlasTexture·발/그림자·포구를 읽는다.
- 지팡이/큰포 각각 실제5방향×6자세=30프레임(뒤 N·뒤사선 NE·측면 E·앞사선 SE·정면 S)을 제작했고 좌측 대응은 반전해8방향을 선택한다. 위를 향할 때 정면 그림을 회전해 대체하지 않는다. 기존 8프레임 시트와 원본도 보존한다. 생물 시트는 별도의12프레임으로 피격·정화·여우 준비/연계를 표현한다.
- 이동 방향은 실제 규칙 위치의 변위, 걷기 위상은 이동 거리로 선택한다(프레임당8논리단위,4자세/주기,최대12자세/초의 임시값). 방향을 바꿔도 위상을 유지하고 멈추면 마지막 방향을 보존한다. 공격은 실제 선택 표적으로 방향을 전환하고 방향별 그림 포구에서 탄/입자가 시작한다. 이동과 공격 방향이 다르면 시전 때 조준 방향이 우선하며 완전한 상·하체 독립 스트레이프는 아직 구현하지 않았다.
- 준비→방출55ms→반동160ms까지→회복290ms까지를 연결하는 임시 타이밍이다. 공격·별비가 승리를 만드는 프레임도 시전 방향을 먼저 보이고 결과로 전환한다. 적 피격의 표정/체형 변화와 짧은 정화 자세, 여우 꼬리/귀·연계 자세를 연결한다. 스프라이트 수/프레임 수 자체를 생동감 수용 기준으로 쓰지 않는다.
- 실제 제품 pause/focus 처리는 유지한다. 캡처만 상속 fixture의 `_handle_lifecycle`로 외부 창 알림과 분리했다. 원본 제품 알림·복귀 회귀와 fixture 격리의 차이를 별도로 검사한다. 마지막 관리 실패 당시 OS 알림 원인은 확정하지 않았다.

설치 Godot4.7.2의 실행으로 제품8,005개와 방향·모션·fixture134개 회귀가 통과했다(`workflow-adoption-20261106/direction-check-2`). 이는 로컬 결과이며 Harness receipt를 생성하거나 기존 BLOCKED를 해제하지 않았다. 이전 단일방향 미리보기96/192장과129장도 과거 단계로 보존한다. 최신 방향/표현 판독 자료와 입력 SHA는 같은 runtime의 `direction-video`·`direction-render`에 생성하며, 고정 **커밋**의 관리 검사·독립 시각/모션 판독은 여전히 필요하다. 이전 완료 조건을 이 로컬 결과로 충족 처리하지 않는다.

실제 제작 방법·프레임 자료의 출처·타이밍과 미검증은 이 브랜치의 기존 [아트 방향](art-direction.md)과 [자산 출처](asset-sources.json)에 연결한다. 이번 문서 채택으로 실행기나 활성 task 입력이 갱신됐다고 표시하지 않는다.

## 버튼·상태창 후속과 현재 경계

원작과 동종 게임의 공식 이미지 검색/직접 판독 후 실제3세션 논의를 수행했다. 결정은 절제한 그림책 마도공방(A), B의 명도 대비만 참고하는 것이다. 자세한 비교·세션ID·QA-01~05의 대응/남은 판정은 [아트 방향](art-direction.md)의 「버튼·상태창 재검토」가 소유한다. 평행 UI 기획 문서를 새로 만들지 않았다.

Root가 실제 도구로 UI그림/9patch를 공급하고 같은 후속 브랜치에 통합했다. 상태값·가격·장착·합성·환생/저장 계약은 실제 함수와 연결한다. 공방 정지 중 별비와 환생 안내 누락은 기존 의미와 일치하도록 수정했다. 결과 노출 전450ms 표현 시간을 두고 이전 안내가 결과에 남지 않게 했다. 규칙/동작/표시의 로컬 검사를 기술·실제 화면·OS입력·사용자 아트 수용으로 분리한다.

기존pin 원문을 검증한 격리 실행 사본의 **공식 add/discuss만** 사용해 새 의존 문서 작업 `ui-design-discussion`(QUEUED)과 회의만 등록했다. 기존3task의 입력/상태/receipt를 직접 수정하지 않았다. 논의3회로 실제 누적은59/60이며 상한/STOP/pin은 불변이다. 위 표의56/60은 채택 시작 때의 스냅샷이다. 현재 남은1회로 전체 제작·검사·독립 검토·통합을 완결할 수 없어 이번 로컬 후속을 정식 수용/커밋/main 반영으로 표시하지 않는다.

최종 로컬 검사·캡처·입력 SHA와 재현 경로는 runtime `workflow-adoption-20261106/`에 보존한다. 기존 BLOCKED를 강제로 재진입하거나 다른 같은 이름 작업으로 지우지 않는다. 사용자 반려/정밀한 모바일 값 조회·고속 보폭·상하체 독립 조준·정령 방향·모든 결과 위치·새 OS입력/청취/기기/사람 평가는 별도 미수용/미검증으로 남긴다. 다음 플레이의 완료 조건 자체는 아래 그대로 유지한다.

## 다음 배정과 확장

아래는 후속 정상 배정의 역할·입출력이다. 새 Worker/Art/독립 리뷰 세션을 실행했다고 표시하지 않으며, 기존 task 입력에 끼워 넣지 않는다. 현재 고정 소스와 결과를 먼저 보존하고 pin에 맞는 정상 Controller 경로가 확보된 뒤에만 후속 작업을 선언한다. BLOCKED 작업을 같은 이름으로 재등록하거나 직접 DB 수정으로 재진입시키지 않는다. 의존 작업은 기존 결과·미해결 finding·이 문서를 명시 입력으로 받아야 하며, CLOSED 의존성만 지원하는 기존 실행기의 제한을 임의 우회하지 않는다.

## 로컬 저장 계약

첫 버전은 로그인 없는 단일 기기 저장이며 네트워크·서버·계정 공유는 없다. `progress_store.gd`가 `user://progress.json`을 사용하고 schema version=1이다.

| 필드 | 의미 |
|---|---|
| schema_version | 포맷 버전. 현재1만 허용 |
| local_owner_id | 최초 생성한 16바이트 난수의 32자리 hex. 로컬 진행 소유권 식별자이며 IdP 인증이 아님 |
| saved_at | 마지막 저장 시각(Unix초) |
| reward_cursor | 보상 산정이 확정된 기준 시각. 시간 역행으로 감소하지 않음 |
| pending_coins | 확정했으나 아직 수령하지 않은 오프라인 별빛 |
| coins / materials | 별빛·정화잎 |
| levels | attack/speed/yield 강화(각0~20) |
| inventory / equipped | 3등급 개수와 장착 등급(-1은 기본 지팡이) |
| spirit / rebirths / boss_cleared | 정령 해금·환생 수·환생 가능 조건 |

메모리의 현재 전투 위치·적·발사체·남은 보스 시간은 저장하지 않는다. 재실행은 저장된 성장 상태로 새 숲 전투를 시작한다. 5초 자동 저장, 성장 행동 및 정상 종료 저장을 제공한다. 강제 프로세스 종료/전원 차단 직전의 미저장 전투 보상은 손실될 수 있다.

쓰기 전 필드/타입/유효 범위를 검증하고 `.tmp`에 쓰기·flush·재파싱 후 rename으로 본 파일을 교체한다. 성공 후 최신 스냅샷을 `.bak`으로 갱신한다. 전체 하드웨어 전원 차단에 대한 영구 저장 보증이나 서버 트랜잭션은 아니다. 성장·수령 시 쓰기 실패는 비용·보상·인벤토리를 이전 상태로 되돌리고 저장 실패 안내를 표시한다.

본 파일이 불량이면 `.invalid-<id>`로 원본을 보존하고 유효한 백업을 찾는다. 백업 복구 시 미수령 보상을 0으로 하고 새 오프라인 보상은 발행하지 않는다. 둘 다 불량이면 원본/백업을 보존하고 새 로컬 진행을 시작한다. 지원하지 않는 포맷도 현재는 불량으로 분류·보존하므로, 후속 버전에서는 마이그레이션 또는 안전한 읽기 전용 안내 정책이 필요하다.

## 최대24시간 오프라인 보상

재접속 때 `gap = min(86400, max(0, now-reward_cursor))`. 분당 `2+rebirths` 별빛을 임시 비율로 사용하고 분 미만은 버림한다. pending은 현재 비율의 24시간분을 상한으로 누적한다. 시작/마지막 정상 저장 시각을 산정 경계로 쓰며 시간 역행에서는 보상을 발행하지 않는다. 미래로 이동했다 돌아온 시계는 cursor가 그 시각에 도달할 때까지 추가 보상이 막힐 수 있다.

프로세스를 유지한 복귀는 처음 받은 PAUSED/FOCUS_OUT에서 현재 메모리와 suspend 시각을 고정한다. 두 bool 사유는 RESUMED/FOCUS_IN이 해당 사유만 해제하며, 단일 종류 알림도 동작한다. 정지 중 전투·보스 시간·성장·수령·스킬·일반 저장은 진행하지 않는다. 둘 다 풀리면 `max(suspend 시각, 기존 reward_cursor)` 이후부터 성공 시각까지 기존 비율/분 버림/24시간 상한/미수령 총량 상한으로 재계산한다. 미래 커서·시계 역행은 지급 및 커서 후퇴를 막는다. 후보를 원자저장한 뒤 한 번 메모리에 반영하고 첫 큰 delta를 버린다. 복귀 저장 실패 동안은 최초 스냅샷에서 성공 시각까지 다시 계산한다. 진입 저장 실패도 현재 메모리를 오래된 파일로 되돌리지 않는다. 정지 중 정상 종료용 저장은 최초 suspend 시점만 확정한다. 저장 실패 후 프로세스가 사라지면 미저장 진행 복구를 보장할 수 없다. 포맷·비율·뽑기·환생 규칙은 유지한다.

로드 시 갱신한 cursor·미수령액을 먼저 디스크에 확정한다. 확정 실패 시 새 보상을 노출하지 않는다. 메뉴 수령은 pending을 0으로 만들고 coins에 더하는 상태를 함께 저장하므로 같은 최신 파일의 재로드·반복 수령으로 같은 보상을 다시 지급하지 않는다. 정상 종료 저장은 활성 실행 시간을 오프라인으로 다시 계산하지 않게 기준을 전진시킨다.

기기 내 파일의 임의 변조·오래된 파일 덮어쓰기·OS 시계 조작을 신뢰 가능한 서버로 판별하지는 않는다. 현재의 일반 재접속 중복 방지와 후속 계정 동기화의 재전송 방지는 별도 범위다.

## 후속 필수 전환: IdP 로그인·기기 간 공유

9C는 선택 후보가 아닌 필수 후속 요구다. 제공자·시점·원격 서비스·비용·정책은 미정이고 현재 구현하지 않았다. 새 계정·서비스·비밀값·유료 상품을 생성하지 않는다.

- 로컬 owner와 향후 account binding을 구분하고 schema 마이그레이션을 명시한다. 처음 로그인할 때 로컬 진행을 계정에 연결/이전할 대상을 사용자에게 보여주며 원본·복구 참조를 보존한다.
- 같은 계정에 이미 원격 진행이 있으면 자동 덮어쓰기하지 않는다. 가져오기/보존/병합 가능 항목/로그아웃 시 로컬 소유권 정책을 구체화하고 충돌·장비/재화 중복을 검토한다.
- 원격 revision·동기화 상태·기기 식별·재전송 idempotency 키를 설계하고 오래된 저장의 덮어쓰기, 동시 로그인과 오프라인 변경 충돌을 처리한다.
- 오프라인 보상은 신뢰 가능한 시간·계정별 reward cursor/원장·수령 idempotency를 사용해 같은 데이터의 재전송·기기 복원·동시 수령으로 중복 발행되지 않게 한다. 인증만 추가해서 완료로 표시하지 않는다.
- 실제 이전/동기화/충돌/복구/중복보상 실패 경로를 구현한 뒤 별도로 검증한다. 서비스 접근·비용과 최종 이전/덮기 정책은 구체 자료로 검토한다.
