## 실제 구현

- `game/assets/art/`의 신규 imagegen PNG 4장을 바이트 그대로 복사했다. 원본 파일은 수정하지 않았다. 시작/성장 마녀는 1312×1199 RGBA, 배경은 1052×1495 RGB, 생물은 2172×724 RGBA다. 각 파일을 직접 보았고 알파와 치수를 확인했다.
- 생물은 AtlasTexture로 씨앗 `(140,144,415,530)`, 가시왕 `(724,0,724,710)`, 여우 `(1558,10,500,700)` 영역을 사용한다. 투명 여백을 제외하면서 이웃 생물이 섞이지 않게 했다. 원본 아틀라스 자체는 편집하지 않았다.
- `storybook.gd`가 전투 상태를 읽어 Sprite2D·탄도·숫자를 갱신한다. 기존 도형 마녀·적·정령·어두운 통로 그리기는 제거했다. 전투 규칙·합성·뽑기·환생·저장 schema는 기존 코드에 남겼다. 시각 입자는 전투 난수를 소비하지 않는다.
- 호흡·반동·피격 흔들림·버튼 눌림은 재사용/회수되는 Tween, 이동은 시뮬레이션 좌표를 따라간다. 작은 지팡이에서 큰 민트황동 포로 교체하며 탄 크기·길이·반동과 낮고 긴 발사음이 커진다. 발사 위치는 그림의 지팡이 끝/포구에 맞춘다.
- `hit_flash.gdshader`를 실제 적 Sprite2D의 ShaderMaterial에 연결하고 피격값을 전달한다. `magic_pulse.gdshader`는 마녀와 여우정령에 연결한다. 이미 텍스처가 적용된 fragment COLOR를 사용해 색/알파의 중복 곱을 피하고, 국소 RGB를 밝히며 전면 bloom·어두운 overlay는 없다. **연결 구현과 GPU 셰이더 컴파일 검증은 별개**다.
- CPUParticles2D 12슬롯, 슬롯당 최대18개(동시 상한216개), 일회 방출 0.65초다. 발사 별/불꽃, 적중 별, 정화·보상 잎을 사용한다. 포화 시 추가 방출을 생략하고 만료 슬롯을 재사용한다. 적은 현재 시뮬레이션의 최대4마리만 표시하며 정화 시 Sprite2D·그림자·Tween을 회수한다. 전투 그림·숫자·입자는 HUD·공방·결과 창보다 뒤에 둔다. 숫자는 최대32개다. 사운드는 기존 6음성 상한이다. 모바일 성능 측정 결과가 아니다.
- 종이 HUD 아래 전투 공간을 넓히고 하단 작업대 제목/설명 여백을 제거했다. 강화 카드는 위력·초당 발사·정화당 보상의 **현재값**과 별빛 가격을 크게 표시한다. 가격 부족·최대·누름·초점 상태에 같은 규칙을 쓴다. 공방은 기존 실제 기능만 제공하며 열면 전투를 멈춘다.

## 이전 회차 기록 (현재 검증 결과로 재사용하지 않음)

시각 교체 구현은 완료했지만 반려 해결의 최종 판정은 대기다. 레퍼런스·제공 자산 직접 확인과 복사 동일성은 확인했다. 당시 재실행 `python3 tests/run.py --artifacts /tmp/witchburst-storybook-current`는 Godot 임포트 중 사용자 디렉터리 생성/에디터 설정 저장/인증서 접근 오류로 실패했다. 로그는 `/tmp/witchburst-storybook-current/import.log`와 `import-engine.log`에 보존했다. 종료 코드는 0이어도 오류 로그 검출로 검사 실행기는 1을 반환했고 smoke·캡처 단계는 실행하지 않았다. 이후 색상 중복 곱·메뉴 위 입자 문제와 배경 종횡비를 코드로 수정했으며, 당시 소스의 Godot 제품 검사는 호스트에서 필요하다. 제품 검사 PASS로 표시하지 않는다. 환경 우회를 위한 GUI·엔진 복제·전역 설정 변경은 하지 않는다.

회귀는 실제 텍스처/아틀라스·사용 재질·포구·입자 회수·시각 갱신의 상태 비변경, 기존 성장/저장/입력 경로를 검사한다. headless 검사는 GPU 컴파일·시각 품질을 입증하지 않는다. 실패한 임포트 뒤 검사를 이어서 혼란스러운 오류/타임아웃을 만들지 않도록 실행기를 즉시 실패 반환하게 했다.

당시 계획은 Controller가 커밋을 고정한 후 `tests/run.py` 제품검사 → 호스트 `render_check.py` 순서로 실제 렌더러를 검증한다. `capture.gd`는 540×960 / 540×1200 / 720×960에서 기존 초기·성장·보스·별비·승리/환생 선택·시간초과·공방·환생 후·합성 가능 상태에 초기/성장 발사 직후를 더한 **11상태×3=33 PNG**를 만드는 것이었다(현재는 위의45장으로 확대). 성장 비교에는 별빛1000·잎16 fixture를 넣고 실제 제작/합성/정령 함수를 사용한다. 자연 보상 승리는 별도 smoke 검사다. `05-won`의 기존 환생 선택과 `08-rebirth`의 초기화 후 복귀를 함께 판독하며 미구현 환생 메뉴를 추가하지 않았다.

### 이전 포구 반려 대응 이력

이전 구현은 기준 포구에 그림을 맞춘 뒤 반동 이동·회전을 더하면서 탄·입자에는 그 변환을 적용하지 않았다. 이전 회귀도 규칙상 탄 좌표와 같은 헬퍼만 비교했다. 기존 변환식의 작은 수치 재현에서 540폭·성장3·최대 반동·호흡1일 때 그림 포구가 약9.17px 왼쪽, 3.86px 위로 벗어났다. 이는 수치 재현이며 실제 렌더러 PNG 관측값은 아니다.

당시 그림의 자식 `Marker2D`에 포구를 두고, 발사 반동과 호흡을 먼저 적용한 실제 변환 좌표를 표현용 탄과 발사 입자의 공통 출발점으로 읽는다. 발사 후 몸이 움직여도 출발점은 유지하고, 당시 탄의 표시 보정은64단위 안에 기존 규칙 궤도로 합류했다(현재는 포신 축·유도 궤적으로 교체). Tween 상태를 충돌·피해·비행시간·저장에 되먹이지 않는다. 탄 참조별 표현 자료는 사격/화면 갱신 때 회수한다.

새 smoke 회귀는 세 비율×네 성장 단계×세 호흡 값에서 최대 반동을 만들고, **원본 픽셀**(시작1061,504.5 / 성장1250,504.5)을 실제 Sprite2D 변환으로 옮겨 그리기에 쓰는 탄과 실제 입자 노드 좌표를 비교한다. 발사 뒤 이동·반동 회복 시 출발점 유지, 비행 후 궤도 합류·자료 회수, 표현 갱신 횟수가 달라도 전투 결과가 같은지도 검사한다. `10-first-shot`·`11-grown-shot` 캡처는 반동/호흡1을 고정한 발사 직후 PNG와 좌표 영수증을 남긴다. 호스트 행렬 검사는 추가 6장 누락·좌표 불일치·최대 반동이 아닌 기록을 거부한다.

그 회차 수정 전 `tests/run.py --artifacts /tmp/witchburst-muzzle-before`는 동일 sandbox 권한 오류로 임포트 실패했으며 로그를 해당 경로에 남겼다. 환경 우회를 반복하지 않았다. 수정 후 Godot smoke·상태 준비·GPU/PNG·독립 판독은 **호스트 검증 대기**다. Python 호스트 계약 검사 5개만 실제 통과했다. 그중 PNG 헤더 fixture는 합성 계약 검사이고 렌더링 증거가 아니다. 포구 반려는 코드 대응을 마쳤으나 실제 발사 직후 PNG 확인 전 해결 PASS로 판정하지 않는다.

현재 독립 리뷰어는 정확한 커밋의 `check-1/render-captures` PNG와 지정 원작 5장을 `view_image`로 직접 비교한다. 캐릭터·배경·버튼·전투의 개선, 장비 성장 대비, 포구/탄도/피격/보상, 세 비율 가독성을 비판적으로 판단한다. 단순한 글자 잘림 없음이나 자동 PASS로 시각 품질을 수용하지 않는다. 새 자산·셰이더·렌더러도 소스 입력 해시에 포함해야 한다.
