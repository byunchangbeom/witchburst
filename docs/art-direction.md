[CanvasItem shader 정본](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html)의 MODEL_MATRIX/varying/fragment 알파 계약을 읽고 설치4.7.2에서 실제 GPU로 확인한다. 셰이더가 걷기를 만들어냈다고 하지 않는다. 다리·팔·몸통 자세는 실제 원본 프레임이고 셰이더는 두 파츠의 선택 영역만 맡는다. 별비 VFX는 기존 고정 필드 좌표 대신 판정 순간의 실제 표적 위치를 기억해 도착하며, 피해/사격 시계·입력 발동은 바꾸지 않는다. 스킬이 적을 제거한 뒤에도 도착 위치를 보존한다.

### 실제 자산과 엔진 연결

- 신규 `witch-{wand,cannon}-directions.png`: 각각6열×5행=30프레임. N/NE/E/SE/S와 좌측 대응 반전으로8방향을 선택한다. 각 셀 알파에서 실제 발 기준과 밝은 별/포구 위치를 읽어 `motion-atlas.json`에 기록했다. 픽셀을 편집하거나 원작 자산을 복사하지 않았다. 방향별 원본·SHA·생성 경로는 asset-sources.json에 있다.
- `living_motion.gd`: 이동 벡터→몸/발 방향, 선택 표적→시전 방향, 그림의 포구→주탄/입자. 얼굴을 위/아래로 회전하거나 정면 그림 하나를 모든 방향에 쓰지 않는다. 발사 준비·방출·반동·회복, 피격·정화·여우 연계는 실제 자세 프레임을 바꾼다.
- 준비는 다음 발사까지120ms 이내, 방출55ms, 반동은160ms까지, 회복은290ms까지가 현재 가설이다. 위치 이동과 자세 상태를 구분한다. 위로 이동·위쪽 공격이면 뒤쪽 행을 사용하고, 별비가 보스를 끝내도 시전 뒤쪽 프레임을 먼저 보여준다. 공격 중에는 표적 방향을 우선한다. 상·하체 독립 조준과 완전한 고속 달리기는 미구현이다.
- 기존 original4 PNG·기존8프레임 시트·배경·UI·셰이더·입자 상한과 규칙·저장을 보존한다. 기존 숨긴 Sprite2D는 표현 좌표 기준이며 실제 시각 검사는 AnimatedSprite2D의 현재 Atlas와 변환을 사용한다. 실제 frame마다 포구·발/그림자·반전 변환을 확인한다.

## 실제 구현

- `game/assets/art/`의 신규 imagegen PNG 4장을 바이트 그대로 복사했다. 원본 파일은 수정하지 않았다. 시작/성장 마녀는 1312×1199 RGBA, 배경은 1052×1495 RGB, 생물은 2172×724 RGBA다. 각 파일을 직접 보았고 알파와 치수를 확인했다.
- 생물은 AtlasTexture로 씨앗 `(140,144,415,530)`, 가시왕 `(724,0,724,710)`, 여우 `(1558,10,500,700)` 영역을 사용한다. 투명 여백을 제외하면서 이웃 생물이 섞이지 않게 했다. 원본 아틀라스 자체는 편집하지 않았다.
- `storybook.gd`가 전투 상태를 읽어 Sprite2D·탄도·숫자를 갱신한다. 기존 도형 마녀·적·정령·어두운 통로 그리기는 제거했다. 전투 규칙·합성·뽑기·환생·저장 schema는 기존 코드에 남겼다. 시각 입자는 전투 난수를 소비하지 않는다.
- 호흡·반동·피격 흔들림·버튼 눌림은 재사용/회수되는 Tween, 이동은 시뮬레이션 좌표를 따라간다. 작은 지팡이에서 큰 민트황동 포로 교체하며 탄 크기·길이·반동과 낮고 긴 발사음이 커진다. 발사 위치는 그림의 지팡이 끝/포구에 맞춘다.
- `hit_flash.gdshader`를 실제 적 Sprite2D의 ShaderMaterial에 연결하고 피격값을 전달한다. `magic_pulse.gdshader`는 마녀와 여우정령에 연결한다. 이미 텍스처가 적용된 fragment COLOR를 사용해 색/알파의 중복 곱을 피하고, 국소 RGB를 밝히며 전면 bloom·어두운 overlay는 없다. **연결 구현과 GPU 셰이더 컴파일 검증은 별개**다.
